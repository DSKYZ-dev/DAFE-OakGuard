# Verification harness

These scripts run real OakScript through the real engine —
`lexer.ts` → `parser.ts` → `validator.ts` → `interpreter.ts` — over synthetic
bars generated by `data-generator.ts`, and assert the results. Nothing here
mocks the runtime: if a script passes, the engine behaved that way.

Run any of them from the repository root:

```bash
npx tsx tools/verify/mega-test.ts
```

| Script | What it exercises |
|---|---|
| `mega-test.ts` | The full sweep — stdlib functions, parsing, validation, interpretation, volume profile, bar transforms. This is `npm test`. |
| `focused-test.ts` | A complex ATR storm: Chandelier stops, volatility bands, manifold/ribbon 3D coherence. This is `npm run verify`. |
| `bar-stress.ts` | 12 bar types × 6 timeframes over 5,000 bars with deterministic volume-profile checks and an engine health check. |
| `extreme-test.ts` | Extreme prices (0.0005 → 1e6), zero-volume bars, NaN inputs and rapid timeframe changes. |
| `adapter-agent-test.ts` | Adapter/movement classes G1–G9 with easy and hard prompts, safeguard assertions and hard visual cases. |
| `adapter-math-audit.ts` | The arithmetic behind the adapter's placement and scaling. |
| `math-audit-test.ts` | Stdlib and engine math against reference implementations (Wilder, Hull, standard definitions). |
| `backtest-stress.ts` | Backtest engine and optimizer: bracket fills, gap handling, in/out-of-sample splitting, log-spaced sweeps. |
| `fix-validation-test.ts` | Regression cases for validator findings — each one a bug that was found and fixed. |
| `llm-dual-test.ts` | Two-model comparison run: does the coder emit valid OakScript (plotshape/input/banned-construct checks) or Pine leaks? |

## What "passing" means

A harness script prints a summary and exits non-zero on a failed assertion. The
assertions are about behaviour, not snapshots: e.g. that a Renko transform emits
monotonic bricks for a monotonic input, that the volume profile's bins sum back
to total volume, that an ATR storm cannot produce NaN stops, that a
`plot3d(..., "3d")` script lands in the same scene as its companion
`plotshape_3d`, and that a validator rejection names the right line.

## Reporting findings

When a script finds something real, it gets written up rather than quietly
patched — see [`../../docs/reports/`](../../docs/reports/). Two of the more
useful examples: the math audit's severity table, and the focused testing
report's G1–G9 movement matrix.
