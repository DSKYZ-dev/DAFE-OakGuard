## Description — long cut

```
It compiled. It validated. And it can never fire.

AI coders now write trading indicators for millions of people — and the code compiles, passes the validator, and is quietly wrong. A 20-bar breakout that fires zero times on 2,400 bars. A moving average that never produces a finite number. A misspelled builtin that silently returns zero. Checkers only catch the bugs somebody already thought of.

OakGuard runs the code, proves when it is broken, and asks Muse Wonder for a rule that would have caught it. The rule is data, never code — it cannot touch the chart, the engine, or your orders. Then a referee the model cannot see grades that rule against broken variants the model never saw, plus 46 known-good scripts. Only rules that pass every gate go live in the editor.

FIRST RUN
• 3 rules promoted, first round
• 174 / 174 broken variants caught
• 58 / 58 held out — a third the model never saw
• 0 / 46 false alarms on known-good scripts
• 9 / 9 deliberately flawed rules rejected by the referee
• $0.10–$0.12 per full run (live run $0.1005 · recorded replay $0.115)

Then I pointed the same oracles at my own engine. They found two interpreter bugs that had been silently killing shipped indicators: a crossover() cache collision and NaN-poisoned sma/ema. Both fixed.

Built on DAFE Charts — my trading terminal — in ten days, October 26 to November 4, 2026. Everything marked NEW was built inside that window.

It certifies the code, not the returns. No equity curves, no P&L, no backtest screenshots: OakGuard grades whether a rule is correct, not whether a strategy is profitable.
```
